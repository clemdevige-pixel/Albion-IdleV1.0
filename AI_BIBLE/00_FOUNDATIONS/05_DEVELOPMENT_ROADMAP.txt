PURPOSE
================================================================================

This document defines the complete development strategy of Albion Idle.

Its objective is to organize development into logical milestones where every
new system expands the previous one without requiring major refactoring.

The roadmap prioritizes delivering a playable game as early as possible while
maintaining a scalable architecture.

This document is a production roadmap.

It does not describe implementation details.

================================================================================
CORE DEVELOPMENT PHILOSOPHY
================================================================================

Development follows five fundamental principles.

1.
Every milestone must produce a playable game.

2.
No system should be implemented before its dependencies exist.

3.
Every new feature must increase replayability.

4.
Temporary placeholder implementations are acceptable if they do not require
future rewrites.

5.
The architecture must always remain extensible.

The project should never become dependent on temporary code.

================================================================================
MILESTONE 1
CORE GAMEPLAY PROTOTYPE
================================================================================

Objective

Create the smallest possible playable version of the game.

The player must already understand the complete gameplay loop.

Required systems

• Character
• Basic Combat
• Enemy Generation
• Inventory
• Equipment
• Loot
• Basic UI
• Save System

Gameplay Loop

Fight

↓

Loot

↓

Equip

↓

Fight Stronger Enemies

Completion Criteria

The player can play continuously for at least one hour without requiring
additional systems.

================================================================================

Required systems

• Refining

• Workers
• Equipment Progression
• Masteries
• Offline Progression

Gameplay Loop

Combat

↓

Resources

↓

Production

↓

↓

Combat

Completion Criteria

Every core gameplay pillar is present.

The game represents the intended final experience on a smaller scale.

================================================================================
MILESTONE 3
CONTENT EXPANSION
================================================================================

Objective

Increase gameplay variety.

Required additions

• More enemies
• More biomes
• More equipment tiers
• Additional resources
• Additional crafting recipes
• More worker specializations
• More island upgrades

Focus

Content quantity.

No major gameplay redesign.

================================================================================
MILESTONE 4
ECONOMY & LONG-TERM PROGRESSION
================================================================================

Objective

Increase long-term player retention.

New systems

• Economy balancing
• Advanced crafting
• Resource sinks
• Advanced progression
• Achievement system
• Statistics
• Additional optimization mechanics

Focus

Long-term progression.

================================================================================
MILESTONE 5
LIVE GAME FEATURES
================================================================================

Objective

Prepare the game for long-term operation.

Potential systems

• Events
• Seasons
• Daily objectives
• Weekly objectives
• Leaderboards
• Prestige
• Future multiplayer interactions
• Cloud Save

Focus

Retention and replayability.

================================================================================
MILESTONE 6
RELEASE CANDIDATE
================================================================================

Objective

Finalize the game.

Tasks

• Bug fixing
• Optimization
• Balancing
• Accessibility improvements
• UX improvements
• Audio polishing
• Visual polishing
• Final testing

The objective is stability rather than new content.

================================================================================
DESIGN VALIDATION
================================================================================

Each milestone must answer the following questions.

Is the game still fun?

Can a new player understand the progression?

Does every gameplay system still reinforce combat?

Does every resource have a purpose?

Does every progression system feel rewarding?

If any answer is "No", development returns to iteration before moving to the
next milestone.

================================================================================
FEATURE ACCEPTANCE RULES
================================================================================

A new feature can only be added if it satisfies at least one of these goals.

• Improves combat.
• Improves progression.
• Improves production.
• Improves decision making.
• Improves replayability.
• Improves player retention.

Features that satisfy none of these goals should not be implemented.

================================================================================
RISK MANAGEMENT
================================================================================

The biggest development risks are:

• Feature creep
• Overengineering
• Excessive automation
• Progression inflation
• Content without gameplay value
• Systems disconnected from the core loop

Every milestone review must verify that these risks remain under control.

================================================================================
SUMMARY
================================================================================

Development always prioritizes gameplay over content.

A small polished feature is more valuable than multiple unfinished systems.

Every milestone produces a complete playable version.

Every new gameplay system strengthens the existing gameplay loop.

The roadmap exists to ensure that Albion Idle grows progressively without
requiring major redesigns while remaining fun at every stage of development.
