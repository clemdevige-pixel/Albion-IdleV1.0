# 17. GATHERING SYSTEM

---

# Purpose

The Gathering System manages every active resource collection performed by the player.

It is responsible for harvesting raw materials from Resource Nodes created during exploration and transforming player interaction into production resources.

Gathering exists to reinforce the crafting economy without replacing combat as the primary gameplay loop.

The Gathering System is responsible for:

- Resource Node interaction
- Gathering validation
- Gathering progression
- Resource generation
- Gathering Masteries
- Gathering tool validation
- Bonus resource generation

The Gathering System is NOT responsible for:

- Resource spawning
- World generation
- Inventory management
- Refining
- Crafting
- Worker production
- Combat

These responsibilities belong to their dedicated systems.

---

# Design Philosophy

The Gathering System follows eight fundamental principles.

---

## Optional Gameplay

Gathering is never mandatory.

Players must always be able to progress through combat, trading and passive production.

Gathering rewards active play without becoming a progression requirement.

---

## Combat First

Combat remains the primary gameplay loop.

Gathering acts as a secondary progression activity.

Resources obtained through gathering ultimately strengthen combat through the production chain.

---

## Resource Production

Gathering produces only raw resources.

These resources must later pass through:

```
Gathering

↓

Refining

↓

Crafting

↓

Equipment
```

The Gathering System never produces finished equipment.

---

## Deterministic

Every gathering action is deterministic.

Given identical:

- Resource Node
- Tool
- Mastery
- Statistics

the result is always identical.

Version 1 contains no gathering failures.

---

## Data Driven

Every Resource Node is defined entirely through configuration.

Examples:

- Resource Family
- Tier
- Charges
- Respawn Duration
- Required Tool
- Bonus Tables

No resource-specific logic is hardcoded.

---

## Simple

The gathering loop intentionally remains straightforward.

```
Reach Node

↓

Gather

↓

Receive Resources

↓

Repeat
```

There are no gathering mini-games in Version 1.

---

## Hero Advantage

The Hero is always more efficient than Workers.

Active gameplay should always outperform passive production.

Workers provide consistency.

The Hero provides efficiency.

---

## Extensible

The architecture supports future additions such as:

- Rare Nodes
- Enchanted Resources
- Territory Bonuses
- Weather Effects
- World Events

Version 1 intentionally implements only the core mechanics.

---

# Responsibilities

The Gathering System is responsible for:

- Node Validation
- Tool Validation
- Gathering Speed
- Resource Generation
- Bonus Resources
- Gathering Mastery Progression

The Gathering System is NOT responsible for:

- Node Placement
- Inventory Storage
- Resource Refining
- Crafting Recipes
- Economy Balance
- Worker Production

---

# Gameplay Loop

The complete gathering loop is:

```
Encounter Completed

↓

Resource Node Available

↓

Gather

↓

Receive Resources

↓

Inventory

↓

Continue Exploring
```

Gathering integrates seamlessly into the exploration loop.

---

# Resource Families

Version 1 supports five primary resource families.

- Wood
- Stone
- Ore
- Fiber
- Hide

Each family participates in at least one refining chain.

---

# Resource Tiers

Resources follow the same progression as equipment.

Tier 1

Novice

Tier 2

Apprentice

Tier 3

Journeyman

Tier 4

Adept

Tier 5

Expert

Tier 6

Master

Tier 7

Grandmaster

Tier 8

Elder

Higher tiers unlock stronger equipment production.

---

# Resource Nodes

Resources exist inside Resource Nodes.

Each Node represents one gatherable object.

Nodes are generated by the Exploration System.

The Gathering System only manages interaction.

---

# Resource Node Definition

Each Resource Node defines:

- Resource Family
- Resource Tier
- Maximum Charges
- Current Charges
- Required Tool Tier
- Respawn Duration
- Bonus Loot Table

Definitions contain no gameplay logic.

---

# Node Lifecycle

Every Resource Node follows the same lifecycle.

```
Spawn

↓

Available

↓

Gather

↓

Charges Reduced

↓

Depleted

↓

Respawn

↓

Available
```

Version 1 supports deterministic respawn behavior.

---

# Gathering Charges

Each Node contains a limited number of Charges.

Each successful gathering action consumes one Charge.

When:

Current Charges = 0

the Node becomes Depleted.

---

# Depleted Nodes

Depleted Nodes cannot be gathered.

After the Respawn Duration expires:

Maximum Charges are restored.

The Node becomes Available again.

---

# Gathering Tools

Every Resource Family requires its dedicated tool.

Wood

↓

Axe

Stone

↓

Hammer

Ore

↓

Pickaxe

Fiber

↓

Sickle

Hide

↓

Skinning Knife

Gathering without the correct tool is impossible.

---

# Tool Progression

Gathering tools follow Tier progression.

Higher Tier tools provide:

- Faster Gathering
- Access to Higher Tier Nodes
- Better Resource Yield
- Higher Bonus Chance

Tool progression mirrors the equipment progression system.

---
# Gathering Validation

Every gathering action begins with a validation phase.

The Gathering System verifies:

- Resource Node Exists
- Resource Node Available
- Resource Node Not Depleted
- Correct Gathering Tool Equipped
- Required Tool Tier Reached
- Player Able to Gather

If any validation fails:

The gathering action is cancelled.

No resources are generated.

---

# Gathering Pipeline

Every gathering action follows the exact same pipeline.

```
Gather Request

↓

Validate Node

↓

Validate Tool

↓

Validate Player

↓

Calculate Gathering Time

↓

Generate Resources

↓

Grant Mastery XP

↓

Reduce Node Charges

↓

Check Depletion

↓

Emit Events

↓

Finished
```

Every gathering action uses this pipeline.

---

# Gathering Request

The AI System generates a Gather Request after defeating a Resource Enemy.

The request contains:

- Player
- Resource Node
- Simulation Tick

The Gathering System performs every remaining step.

---

# Resource Enemy Integration

Version 1 does **not** contain free-standing gathering nodes during exploration.

Gathering Nodes are generated **only** after defeating a Resource Enemy.

Examples:

- Ore Elemental
- Ancient Tree
- Stone Golem
- Giant Boar
- Living Plant

Combat therefore remains the primary source of gathering opportunities.

---

# Resource Node Creation

When a Resource Enemy dies:

```
Enemy Death

↓

Enemy System

↓

Resource Node Spawn

↓

Gathering Available
```

The Resource Node inherits its configuration from the defeated enemy.

Example:

Ore Elemental

↓

Tier 5 Ore Node

---

# Automatic Gathering

Once combat has ended:

```
Looting

↓

Gathering

↓

Continue Exploring
```

The Hero automatically gathers the Resource Node.

No manual input is required.

The AI System generates the Gather Request.

---

# Gathering Speed

Gathering requires a fixed duration.

Gathering Speed is influenced by:

- Tool Tier
- Gathering Mastery
- Equipment Bonuses

Future versions may add:

- Consumables
- Temporary Buffs

Workers never benefit from Hero Gathering Speed.

---

# Gathering Formula

Version 1 uses a deterministic formula.

```
Final Gathering Time

=

Base Time

×

Tool Modifier

×

Mastery Modifier
```

No randomness is applied.

---

# Gathering Success

Gathering never fails.

If validation succeeds:

Resources are always generated.

Version 1 contains:

- No Failure Chance
- No Skill Checks
- No Mini-games

The player's progression improves efficiency rather than success rate.

---

# Resource Generation

Every successful gathering action generates one or more resources.

Generation is determined by:

- Resource Family
- Resource Tier
- Node Definition

The Gathering System creates a Resource Grant.

Inventory management is handled separately.

---

# Bonus Resources

Some gathering actions may generate bonus rewards.

Possible bonuses include:

- Extra Resource
- Rare Material
- Enchanted Resource (Future)
- Refining Catalyst (Future)

Bonus generation is defined through data.

---

# Gathering Mastery

Each Resource Family has an independent Gathering Mastery.

Examples:

- Wood Gathering
- Ore Gathering
- Fiber Gathering
- Stone Gathering
- Hide Gathering

Masteries increase only through active gathering.

---

# Mastery Progression

Every successful gathering action grants Gathering Experience.

```
Gather Resource

↓

Gathering XP

↓

Gathering Mastery

↓

Improved Gathering
```

Mastery progression is permanent.

---

# Mastery Benefits

Increasing Gathering Mastery improves:

- Gathering Speed
- Resource Yield
- Bonus Resource Chance

Future versions may unlock:

- Specializations
- Rare Node Access
- Advanced Bonuses

---

# Resource Yield

Every Resource Node defines a Base Yield.

Final Yield is calculated using:

- Base Yield
- Tool Modifier
- Mastery Modifier
- Bonus Modifiers

Version 1 uses deterministic calculations only.

---

# Inventory Integration

Generated resources are transferred to the Inventory System.

The Gathering System never stores resources directly.

Pipeline:

```
Resource Generation

↓

Inventory System

↓

Inventory Updated
```

---

# Storage Overflow

If Inventory capacity is exceeded:

Overflow handling is delegated to the Inventory System.

The Gathering System remains independent from storage rules.

---
# Hero vs Workers

The Hero and Workers intentionally fulfill different production roles.

## Hero

- Active gameplay
- Immediate gathering
- Faster gathering speed
- Higher resource yield
- Better bonus resource chance
- Requires player interaction

## Workers

- Passive production
- Scheduled output
- Slower gathering
- Predictable production
- No bonus resources (Version 1)
- No player interaction

The Hero should always outperform Workers while actively gathering.

---

# Gathering Equipment

Certain equipment may improve gathering performance.

Possible bonuses include:

- Gathering Speed
- Resource Yield
- Bonus Resource Chance

Gathering bonuses never improve combat performance.

Likewise, combat bonuses never improve gathering unless explicitly stated.

---

# Gathering Statistics

The Gathering System uses a small set of dedicated statistics.

Version 1 supports:

- Gathering Speed
- Resource Yield
- Bonus Resource Chance

Future versions may introduce additional gathering-specific attributes.

---

# Multiple Resource Families

Each Gathering Mastery progresses independently.

Example:

```
Ore Gathering

Level 12
```

does not improve

```
Wood Gathering

Level 4
```

Players are encouraged to specialize through repeated gathering.

---

# Gathering Events

Every successful gathering action emits gameplay events.

Supported events include:

- OnGatherStarted
- OnGatherCompleted
- OnResourcesGenerated
- OnMasteryExperienceGranted
- OnNodeDepleted

The Gathering System never communicates directly with other gameplay systems.

---

# Event Subscribers

Typical subscribers include:

- UI System
- Inventory System
- Statistics System
- Quest System
- Achievement System
- Audio System
- VFX System
- Analytics

All communication occurs through events.

---

# Runtime Validation

Every Gather Request performs runtime validation.

Validation includes:

- Valid Player
- Valid Resource Node
- Node Not Depleted
- Correct Tool Equipped
- Required Tool Tier
- Valid Node Configuration

Invalid requests are safely discarded.

---

# Invalid Resource Nodes

Gathering cannot begin if:

- Node does not exist
- Node is already depleted
- Node has invalid data
- Node has been removed
- Node belongs to another active interaction

The request is cancelled immediately.

---

# Invalid Gathering Tools

If the equipped tool:

- Does not match the Resource Family
- Is below the required Tier
- Is missing

the gathering action fails validation.

No resources are generated.

---

# Runtime Performance

The Gathering System should avoid:

- Runtime allocations
- Dynamic object creation
- Reflection
- Expensive searches

Recommended implementation:

- Cached Node Definitions
- Fixed Gathering Requests
- Constant-time validation

Gathering should scale efficiently regardless of world size.

---

# Relationship with Other Systems

The Gathering System receives data from:

- Exploration System
- Enemy System
- Character System

It interacts with:

- Inventory System
- Mastery System
- Statistics System

It never performs their responsibilities.

---

# Future Compatibility

The architecture intentionally supports future gathering mechanics.

Possible additions include:

- Rare Nodes
- Enchanted Nodes
- Legendary Resources
- Territory Bonuses
- Gathering Potions
- Weather Effects
- Seasonal Events
- Resource Festivals
- Gathering Specializations

These mechanics extend the existing pipeline without replacing it.

---

# Acceptance Criteria

The Gathering System is considered complete for Version 1 when:

- Every Resource Enemy generates the appropriate Resource Node.
- Gathering only occurs after defeating a Resource Enemy.
- Every gathering action follows the shared Gathering Pipeline.
- Correct tools are required for every Resource Family.
- Tool Tier restrictions are enforced.
- Gathering never fails after successful validation.
- Gathering Speed is deterministic.
- Resource Yield is deterministic.
- Gathering Masteries progress independently.
- Resources are transferred to the Inventory System.
- Gathering emits gameplay events.
- Workers remain less efficient than the Hero.

---

The following rules define the Gathering System and must never change without redesigning the project.

Rule 01

Rule 02

Rule 03

Rule 04

Gathering opportunities are created only by defeating Resource Enemies.

Rule 05

Every gathering action follows the shared Gathering Pipeline.

Rule 06

Gathering never fails after successful validation.

Rule 07

Every Resource Family requires its dedicated gathering tool.

Rule 08

Tool Tier restrictions are always enforced.

Rule 09

Gathering Masteries progress independently.

Rule 10

The Hero always gathers more efficiently than Workers.

Rule 11

Rule 12

Rule 13

Rule 14

Future gathering mechanics extend the existing pipeline rather than replacing it.

---

# Summary

The Gathering System provides a deterministic and modular framework for active resource collection. Gathering opportunities are generated exclusively through Resource Enemies, ensuring that combat remains the core gameplay activity while production resources are earned naturally through exploration. The system validates every Gather Request, calculates gathering time, generates resources, progresses Gathering Masteries and emits gameplay events, while remaining completely independent from inventory management, refining and crafting. This architecture guarantees a simple, scalable and extensible production loop that rewards active play without disrupting the idle RPG experience.
