# 41_UI_SYSTEM

## Purpose

The UI System provides a scalable, modular, and highly responsive user interface architecture for the entire game.

It defines:

- HUD architecture
- Window management
- Navigation
- User interactions
- Dashboard
- Notifications integration
- Command Palette
- Favorites
- Loading states
- UI feedback
- Input routing
- UI communication

The UI System never contains gameplay logic.

It only visualizes game state and dispatches user intentions.

---

# Design Goals

The UI must be:

- Fast
- Clean
- Readable
- Non intrusive
- PC-first
- Keyboard friendly
- Mouse friendly
- Future-proof
- Highly modular

The interface should support thousands of hours of gameplay without becoming difficult to navigate.

---

# Core Philosophy

Gameplay should never be interrupted by UI.

The player should always be able to:

- monitor progression
- open management windows
- inspect equipment
- manage workers
- craft
- refine
- check notifications

while combat continues automatically.

Only critical dialogs are allowed to pause interaction.

---

# UI Architecture

The interface is divided into independent modules.

```text
UI Root

├── HUD
├── Window Manager
├── Dashboard
├── Notification Center
├── Command Palette
├── Tooltip Manager
├── Context Menu Manager
├── Modal Manager
├── Loading Manager
├── Feedback Manager
├── Input Manager
└── Event Bus
```

Each module is isolated.

No module directly depends on another whenever event-driven communication is possible.

↓

↓

- Non draggable
- Non resizable

---

---

---

# Reconnection Flow

When connection is lost:

A non intrusive banner appears.

Example:

Connection Lost

Reconnecting...

The UI remains open.

The client retries automatically.

If reconnection succeeds:

Connection Restored

is displayed.

If reconnection ultimately fails:

The player is redirected to authentication.

# Performance Requirements

UI updates must be event-driven.

Avoid polling whenever possible.

Lists should support virtualization for large datasets.

Expensive UI refreshes must be incremental.

Widgets refresh only when their data changes.

Animations must never block gameplay.

# Responsibilities

The UI System is responsible for:

- Presenting game information
- Receiving player input
- Managing windows
- Managing navigation
- Managing dashboard widgets
- Displaying notifications
- Showing feedback
- Managing loading states
- Routing UI events

The UI System is NOT responsible for:

- Gameplay rules
- Combat logic
- Saving
- Progression calculations
- Inventory calculations
- Crafting calculations
- AI decisions
- Economy logic

Those responsibilities belong to their respective systems.
