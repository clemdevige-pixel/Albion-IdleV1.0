# 42_SETTINGS_SYSTEM

## Purpose

The Settings System manages all player-configurable options.

It provides a centralized, modular, and extensible framework for storing, applying, validating, and synchronizing game settings.

The system supports:

- Gameplay Settings
- Graphics Settings
- Audio Settings
- Interface Settings
- Controls
- Language
- User Profiles
- Cloud Synchronization
- Local Machine Settings

The Settings System contains no gameplay logic.

Its only responsibility is managing user preferences.

---

# Design Goals

The Settings System must be:

- Easy to understand
- Fast
- Modular
- Safe
- Extensible
- Platform-independent
- Account-aware
- Hardware-aware

Every setting must have predictable behavior.

---

# Core Philosophy

The majority of settings should apply immediately.

Only settings that may negatively affect the player experience require confirmation or restart.

Players should never lose their preferences unexpectedly.

---

# Apply Modes

Three apply modes exist.

## Immediate

Changes are applied instantly.

Examples:

- Volume
- UI Scale
- Feedback Level
- Animations
- Keybindings
- Language (when supported)

---

## Confirm

Changes are applied temporarily.

The player must confirm.

If confirmation expires, previous values are restored.

Examples:

- Resolution
- Fullscreen
- Refresh Rate

---

## Restart Required

Changes are saved immediately.

They become active after restarting the game.

Examples:

- Future Rendering API
- Future Graphics Backend
- Future Engine Options

---

# Confirmation Flow

For Confirm settings:

Player changes Resolution

↓

Resolution changes

↓

15 second confirmation dialog

↓

Confirm

↓

Setting saved

or

Timeout

↓

Previous resolution restored

---

# Restart Flow

For Restart Required settings:

Player changes option

↓

Setting saved

↓

Message displayed

"This setting will take effect after restarting the game."

No restart is forced.

---

# Pending Changes Banner

Whenever unapplied changes exist, a global banner is displayed.

Example:

```text
You have unapplied changes.

[Apply]

[Discard]
```

The banner disappears automatically after:

- Applying changes
- Discarding changes

Restart-required settings display:

```text
Some changes will take effect after restarting the game.
```

# First Login

When logging in on a new machine:

Cloud Settings are downloaded.

↓

Local Settings are created using hardware defaults.

↓

Player immediately recovers personal preferences while maintaining hardware compatibility.

---

# Conflict Resolution

Cloud Settings use:

Last Write Wins

Local Settings never synchronize.

This guarantees deterministic behavior.

# Validation

Each setting validates its value before being applied.

Examples:

Volume

Minimum:

0

Maximum:

100

Resolution

Must exist on current monitor.

Keybindings

Cannot violate reserved shortcuts.

Invalid values are rejected.

---

# Default Values

Every setting has a default value.

These values are defined by the developers.

Defaults may differ between Cloud and Local settings.

---

---

# Keybinding Management

Keybindings use the Input Action System.

Players may:

Rebind

Restore Defaults

Resolve Conflicts

---

# Language Switching

If supported by the Localization System:

Language changes immediately.

Otherwise:

Language becomes active after restart.

The Apply Mode defines the behavior.

---

# Graphics Safety

Dangerous graphics changes always use confirmation.

The player is never left with an unusable display configuration.

Timeout restores the previous configuration automatically.

---

# Save Behavior

Cloud Settings save automatically.

Local Settings save automatically.

No manual save button exists.

---

# Error Handling

If saving fails:

The player receives a non-intrusive notification.

The previous values remain active.

Settings are never partially corrupted.

---

# Performance Requirements

Settings must load during authentication.

Lookup must be O(1).

Search must remain responsive regardless of the number of settings.

Profiles should switch instantly.

No gameplay frame should depend on Settings processing.

---

---

# Responsibilities

The Settings System is responsible for:

- Managing user preferences
- Validating settings
- Applying settings
- Synchronizing Cloud preferences
- Managing Local preferences
- Managing profiles
- Searching settings
- Resetting preferences

The Settings System is NOT responsible for:

- Rendering
- Audio playback
- Input processing
- UI rendering
- Localization
- Authentication

Those responsibilities belong to their respective systems.
