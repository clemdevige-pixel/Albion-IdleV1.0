# 34. CLIENT RENDERING & UI

---

# 1. Purpose

This document defines the complete client architecture.

It specifies:

- Client responsibilities
- Rendering pipeline
- React architecture
- Phaser architecture
- Scene management
- UI framework
- HUD
- Input system
- Camera
- Animation
- Audio
- VFX
- Asset usage
- Client state
- Network synchronization

The client is responsible for presentation only.

The server remains authoritative for gameplay.

---

# 2. Locked Decisions

---

## 2.1 Client Responsibilities

The client is responsible for:

- Rendering
- Animations
- Camera
- UI
- Input
- Audio
- Visual Effects
- Presentation Timeline
- Local Feedback

The client is NOT responsible for:

- Loot
- Damage calculation
- XP calculation
- Currency
- Crafting results
- Save validation
- Background progression
- Combat resolution

---

## 2.2 Framework Split

React owns the application.

Phaser owns the game world.

```text
React

↓

Application

↓

HUD

↓

Menus

↓

Inventory

↓

Equipment

↓

Settings

↓

Notifications
```

```text
Phaser

↓

World

↓

Characters

↓

Enemies

↓

Projectiles

↓

Particles

↓

Backgrounds

↓

Camera
```

Neither framework replaces the other.

---

## 2.3 Rendering Style

The game is:

```text
2D

Side Scroller

Pixel Art

Horizontal
```

---

## 2.4 Fixed Resolution Philosophy

The game targets one virtual resolution.

Recommended

```text
1920 × 1080
```

Everything scales from that resolution.

---

## 2.5 Pixel Perfect

Rendering must preserve pixel art.

Required

- Integer scaling
- No texture filtering
- Pixel snapping
- Nearest Neighbor filtering

Forbidden

- Blur
- Bilinear filtering
- Fractional scaling

---

# 48. Acceptance Criteria

Client implementation is complete when

- React owns the UI.
- Phaser owns rendering.
- Camera follows smoothly.
- Pixel art remains crisp.
- HUD updates from DTOs.
- Timeline drives animations.
- Combat remains presentation only.
- Tooltips use definitions.
- Inventory is data-driven.
- Assets are loaded through manifests.
- Weather is presentation only.
- Audio categories work independently.
- UI is localized.
- Accessibility settings apply immediately.
- Rendering reaches target performance.

---

# 49. Final Summary

The client is a presentation layer built on React and Phaser.

```text
Server DTO

↓

Client State

↓

Timeline

↓

Animation

↓

Rendering

↓

Player
```

The client never owns gameplay truth.

It renders the authoritative world received from the backend while providing smooth visuals, responsive UI and a polished player experience.
