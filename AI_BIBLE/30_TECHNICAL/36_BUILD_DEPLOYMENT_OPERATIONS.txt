# 36. BUILD, DEPLOYMENT & OPERATIONS

---

# 1. Purpose

This document defines how the project is built, validated, deployed, operated and maintained.

It specifies:

- Development environments
- Build pipeline
- Continuous Integration
- Continuous Deployment
- Release workflow
- Environment configuration
- Database migrations
- Asset packaging
- Rollback strategy
- Secrets management
- Backup strategy
- Production operations

This document is the source of truth for everything between writing code and running the game in production.

---

# 2. Locked Decisions

---

## 2.1 One Codebase

Development, staging and production all use the same codebase.

Only configuration changes.

Code never changes per environment.

---

## 2.2 Build Once

Every release is built exactly once.

The generated artifact is promoted between environments.

Never rebuild for staging or production.

---

## 2.3 Immutable Releases

A deployed version is immutable.

Never edit production files manually.

Every change creates a new release.

---

## 2.4 Infrastructure as Code

Every environment must be reproducible.

Manual server configuration is forbidden.

---

## 2.5 Automated Deployment

Production deployment is fully automated.

Manual deployment steps should not exist.

---

# 3. Environments

The project defines four environments.

```text
Development

↓

Testing

↓

Staging

↓

Production
```

---

## 3.1 Development

Purpose

Local development.

Characteristics

- Hot Reload
- Debug Tools
- Development Assets
- Verbose Logs
- Mock Services Allowed

---

## 3.2 Testing

Purpose

Automated validation.

Characteristics

- Clean Database
- Automated Tests
- CI Pipeline
- Deterministic Fixtures

---

## 3.3 Staging

Purpose

Production validation.

Characteristics

- Same configuration as Production
- Production Build
- Real Database Structure
- Smaller Dataset
- Internal Access

---

## 3.4 Production

Purpose

Public service.

Characteristics

- Optimized Build
- Monitoring
- Metrics
- Automatic Backups
- Debug Disabled

- Database Password

# 16. Migration Rules

# 39. Acceptance Criteria

Deployment pipeline is complete when

- Builds are reproducible.
- CI validates every commit.
- CD deploys immutable artifacts.
- Environment variables are validated.
- Secrets remain secure.
- Database migrations are versioned.
- Save migrations are automatic.
- Static assets are optimized.
- Monitoring detects failures.
- Backups are automated.
- Rollback is documented.
- Production is reproducible.
