# BOSS DATABASE

Version: 1.0

This document defines every boss available in Version 1.

Each boss references the corresponding visual asset defined in
**41_ASSET_MANIFEST.md**.

Numerical values are not stored directly in this document.

Boss statistics, abilities, loot, encounter behaviour and progression values
are inherited from the profiles referenced by each entry.

---

# ============================================================================
# DATABASE RULES
# ============================================================================

Boss ID:
Permanent gameplay identifier.

Asset ID:
Identifier of the boss sprite.

Icon ID:
Identifier used in the interface, bestiary and encounter selection.

Scaling Profile:
Defines HP, damage, armor, resistances, speed and experience rewards.

Ability Profile:
Defines every active and passive boss ability.

AI Profile:
Defines combat phases, targeting rules and movement behaviour.

Loot Profile:
Defines every possible reward.

Spawn Profile:
Defines where and under which conditions the boss may appear.

Encounter Profile:
Defines arena rules, phase transitions, adds and special mechanics.

Generated boss identifiers follow this format:

BOS-0001-T4
BOS-0001-T5
BOS-0001-T6
BOS-0001-T7
BOS-0001-T8

Generated boss assets follow the same format.

Example:

Gameplay Entity:
BOS-0001-T6

Boss Asset:
BOS-0001-T6

Interface Icon:
ICO-BOS-0001-T6

Display Name:
Undead Commander T6

# ============================================================================
# ENCOUNTER RULES
# ============================================================================

Every boss encounter must contain at least one mechanic that prevents the
player from relying only on automatic basic attacks.

Possible mechanics include:

- Area attacks
- Charge attacks
- Summoned monsters
- Temporary invulnerability
- Interruptible casting
- Defensive shields
- Enrage phases
- Ground hazards
- Target marking
- Forced movement
- Healing phases
- Weak-point phases

Each encounter must remain readable in the horizontal combat presentation.

No boss may use more than three simultaneous high-priority visual mechanics.

Area attacks must use clear telegraphs before dealing damage.

Summoned units must use monster IDs already defined in
**DB_MONSTERS.md**.

Encounter mechanics must not require direct character movement input if the
core idle combat system does not support free movement.

In that case, mechanics are resolved through:

- Equipment power
- Ability timing
- Defensive cooldowns
- Interrupt abilities
- Resistance checks
- Damage checks
- Healing checks
- Automatic positioning states

---

# ============================================================================
# PHASE RULES
# ============================================================================

Boss phases are triggered by one or more of the following conditions:

- Remaining HP percentage
- Elapsed combat time
- Summoned unit defeat
- Shield destruction
- Interrupted ability
- Player damage threshold
- Encounter-specific event

Standard phase thresholds:

Phase 1:
100% to 70% HP

Phase 2:
Below 70% HP

Phase 3:
Below 35% HP

These thresholds may be overridden by the Encounter Profile.

Phase transitions must not reset boss HP.

Phase transitions may modify:

- Ability rotation
- Attack speed
- Damage profile
- Summoning behaviour
- Defensive values
- Visual effects
- Animation state
- Arena hazards

# ============================================================================
# GENERATION RULES
# ============================================================================

Every boss generates tier variants according to its Tier Range.

Example:

Base Boss:
BOS-0001

Generated Variants:
- BOS-0001-T4
- BOS-0001-T5
- BOS-0001-T6
- BOS-0001-T7
- BOS-0001-T8

Each generated variant receives:

- The same boss name
- The same faction
- The same role
- The same boss rank
- The same ability profile
- The same AI profile
- The same loot profile
- The same spawn profile
- The same encounter profile
- The tier-specific visual asset
- The tier-specific interface icon
- Statistics generated from its scaling profile
- Rewards generated from its loot profile
- Encounter values generated from its encounter profile

Only the following values may be generated procedurally:

- HP
- Damage
- Armor
- Magic Resistance
- Attack Speed
- Ability Power
- Summoned Unit Tier
- Experience Reward
- Silver Reward
- Loot Quantity
- Loot Quality
- Enrage Timer
- Phase Threshold Modifiers

No generated system may modify:

- Boss ID
- Boss name
- Asset ID
- Icon ID
- Faction
- Role
- Boss Rank
- Ability Profile
- AI Profile
- Loot Profile
- Spawn Profile
- Encounter Profile
