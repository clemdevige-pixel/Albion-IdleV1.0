# CONSUMABLE DATABASE

Version: 1.0

This document defines every consumable item available in Version 1.

Consumables are temporary-use items that apply immediate effects, timed buffs,
healing, energy restoration or utility effects.

Each consumable references the corresponding icon asset defined in
**41_ASSET_MANIFEST.md**.

Numerical values are not stored directly in this document.

Effect strength, duration, cooldown, crafting costs and progression requirements
are inherited from the profiles referenced by each entry.

---

# ============================================================================
# DATABASE RULES
# ============================================================================

Consumable ID:
Permanent gameplay identifier.

Icon ID:
Identifier used in the inventory, merchant, crafting and combat interfaces.

Consumable Type:
Defines the item's main behaviour.

Effect Profile:
Defines the effect applied when the item is consumed.

Scaling Profile:
Defines effect strength and duration by tier.

Craft Profile:
Defines required materials, crafting time and crafting cost.

Acquisition Profile:
Defines alternative acquisition methods.

Cooldown Group:
Defines which consumables share a cooldown.

Usage Context:
Defines where the item may be used.

All consumable variants inherit the same base entry.

Generated identifiers follow this format:

CON-0001-T2
CON-0001-T3
CON-0001-T4
CON-0001-T5
CON-0001-T6
CON-0001-T7
CON-0001-T8

Generated icon identifiers follow the same format.

Example:

Gameplay Item:
CON-0001-T5

Inventory Icon:
ICO-CON-0001-T5

Display Name:
Healing Potion T5

# ============================================================================
# CONSUMABLE TYPE RULES
# ============================================================================

## Potions

Potions provide immediate or short-duration effects.

Potions may be used during combat.

All standard potions share the same global potion cooldown.

A player may carry multiple potion types but may equip only one active potion
type in the combat quick slot unless otherwise defined.

Potion effects are removed when their duration expires.

---

## Food

Food provides long-duration effects.

Food cannot be consumed during active combat.

Only one food effect may be active at a time.

Consuming a new food replaces the previous food effect.

Food duration continues during:

- Combat
- Travel
- Gathering
- Crafting
- Offline progression

Food duration may pause while the player is logged out if the progression
rules explicitly require it.

---

## Bandages

Bandages restore health over time.

Bandage healing is interrupted when the player receives direct damage.

Damage-over-time effects may interrupt bandages if defined by the Effect
Profile.

Bandages use an independent cooldown group.

Bandages do not share the potion cooldown.

---

## Utility Consumables

Utility consumables affect non-combat activities.

Possible affected systems include:

- Gathering
- Travel
- Crafting
- Refining
- Progression
- Mount recovery

Utility effects may coexist with one food effect and one potion effect unless
their Effect Profile explicitly prevents stacking.

---

## Scrolls

Scrolls grant immediate progression effects.

Scrolls cannot be consumed during combat.

Scroll rewards are applied immediately.

Scrolls do not create permanent item identities beyond their canonical
Consumable ID.

---

## Containers

Containers generate rewards when opened.

Containers may reference:

- Fixed rewards
- Weighted loot tables
- Guaranteed currencies
- Tier-scaled rewards
- Faction rewards
- Boss rewards

Opening a container permanently destroys the container item.

---

# ============================================================================
# EQUIPMENT AND QUICK-SLOT RULES
# ============================================================================

The player has dedicated consumable quick slots.

Recommended Version 1 quick slots:

- One Potion Slot
- One Bandage Slot
- One Food Slot
- One Utility Slot

Food is activated outside combat and remains active for its duration.

The Potion Slot controls which potion may be used automatically or manually
during combat.

The Bandage Slot controls which bandage may be used automatically or manually.

The Utility Slot controls the active non-combat consumable.

Consumables do not occupy weapon, armor, off-hand or mount slots.

---

# ============================================================================
# AUTOMATIC USAGE RULES
# ============================================================================

The idle combat system may use eligible consumables automatically.

Automatic potion usage may be triggered by:

- Health below threshold
- Energy below threshold
- Boss phase
- Defensive danger state
- Offensive burst state
- Debuff state

Automatic bandage usage may be triggered by:

- Combat ending
- No recent incoming damage
- Health below threshold
- Encounter transition

Automatic usage requires:

- Consumable available in inventory
- Consumable assigned to quick slot
- Cooldown available
- Valid usage context
- Trigger condition satisfied

Automatic usage thresholds are configured in the player's automation settings.

---

# ============================================================================
# COOLDOWN RULES
# ============================================================================

Cooldown groups prevent repeated use of similar consumables.

Standard cooldown groups:

- COOLDOWN_POTION
- COOLDOWN_BANDAGE
- COOLDOWN_FOOD
- COOLDOWN_UTILITY_TRAVEL
- COOLDOWN_UTILITY_GATHERING
- COOLDOWN_SCROLL

Items within the same cooldown group share cooldown progression.

Using one potion activates the cooldown of every consumable assigned to
COOLDOWN_POTION.

Food uses a replacement rule instead of a standard short cooldown.

Containers do not use a cooldown unless their acquisition profile requires one.

Cooldown values are defined in **DB_PROGRESS_RULES.md**.

---

# ============================================================================
# EFFECT STACKING RULES
# ============================================================================

Effects from the same Consumable Family do not stack unless explicitly allowed.

When a new effect replaces an existing effect, the new effect uses its full
duration.

Effects from different categories may coexist.

Examples of valid combinations:

- One Food effect
- One Potion effect
- One Bandage effect
- One Utility effect

Effects with the same Effect Profile never stack.

Permanent progression rewards are not treated as temporary buffs.

---

# ============================================================================
# EFFECT REMOVAL RULES
# ============================================================================

Temporary effects may end through:

- Duration expiration
- Character defeat
- Effect replacement
- Cleansing
- Activity completion
- Leaving an eligible context
- Encounter-specific rule

Food effects normally persist through character defeat.

Potion effects normally end on character defeat.

Utility effects follow their individual Effect Profile.

---

# ============================================================================
# TIER RULES
# ============================================================================

Consumable tier determines:

- Effect strength
- Effect duration
- Required crafting materials
- Crafting cost
- Item value
- Progression requirement
- Reward quantity

A higher-tier consumable must provide a meaningful improvement.

Higher tiers may improve:

- Strength only
- Duration only
- Both strength and duration
- Reward quantity
- Usage efficiency

A consumable's core behaviour cannot change between tiers.

Example:

Healing Potion T4 and Healing Potion T8 both restore health.

The T8 variant may restore more health but does not become a different
consumable family.

---

# ============================================================================
# ENCHANTMENT RULES
# ============================================================================

Standard consumables are not enchantable.

Effect variation is handled through:

- Tier
- Consumable family
- Scaling Profile
- Item rarity
- Special reward variant

Future exceptional consumables may use rarity variants without modifying their
base identity.

---

# ============================================================================
# STACKING RULES
# ============================================================================

Consumables are stackable.

A stack may contain only items with the same:

- Consumable ID
- Tier
- Binding state
- Special variant
- Expiration state

Consumables with different tiers cannot share the same stack.

Maximum stack size is defined in **DB_PROGRESS_RULES.md**.

Consuming an item reduces its stack quantity by one.

At zero quantity, the stack is removed.

---

# ============================================================================
# CRAFTING RULES
# ============================================================================

Craftable consumables require a valid Craft Profile.

Consumable crafting may require:

- Fiber
- Cloth
- Hide
- Leather
- Wood
- Creature materials
- Herbs
- Food ingredients
- Silver
- Crafting station
- Crafting time

Version 1 may treat herbs and food ingredients as secondary crafting
components defined directly in **DB_CRAFTING.md**.

They do not require separate world-resource families unless gathering gameplay
is expanded.

Crafted consumables preserve the recipe tier.

---

# ============================================================================
# ACQUISITION RULES
# ============================================================================

Consumables may be acquired through:

- Crafting
- Merchant purchase
- Monster loot
- Boss loot
- Task rewards
- Progression milestones
- Loot containers
- Daily rewards
- Expedition rewards

Every acquisition source must reference a canonical Consumable ID.

Procedural systems may generate:

- Tier
- Quantity
- Binding state
- Reward source

Procedural systems may not generate new consumable identities.

---

# ============================================================================
# BINDING RULES
# ============================================================================

Consumables may be:

- Tradable
- Account Bound
- Character Bound
- Conditional

Crafted consumables are normally tradable.

Task and progression consumables may be bound.

A bound consumable cannot be sold or traded.

Binding state does not modify the consumable's effect.

# ============================================================================
# GENERATION RULES
# ============================================================================

Each consumable generates tier variants according to its Tier Range.

Example:

Base Consumable:
CON-0001

Generated Variants:
- CON-0001-T2
- CON-0001-T3
- CON-0001-T4
- CON-0001-T5
- CON-0001-T6
- CON-0001-T7
- CON-0001-T8

Each generated variant receives:

- The same consumable name
- The same consumable type
- The same consumable family
- The same Effect Profile
- The same Scaling Profile
- The same Craft Profile
- The same Acquisition Profile
- The same Cooldown Group
- The tier-specific inventory icon
- Values generated from its profiles

Only the following values may be generated procedurally:

- Effect strength
- Effect duration
- Cooldown duration
- Crafting quantity
- Crafting duration
- Crafting cost
- Required material quantity
- Purchase price
- Sale price
- Reward quantity
- Stack quantity
- Binding state

No generated system may modify:

- Consumable ID
- Consumable name
- Consumable type
- Consumable family
- Icon ID
- Effect Profile
- Scaling Profile
- Craft Profile
- Acquisition Profile
- Cooldown Group
- Usage Context
- Target Type
