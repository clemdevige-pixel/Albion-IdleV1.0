# MOUNT DATABASE

Version: 1.0

This document defines every usable mount available in Version 1.

Each mount references the corresponding visual asset defined in
**41_ASSET_MANIFEST.md**.

Numerical values are not stored directly in this document.

Movement speed, carrying capacity, durability, recovery costs and progression
values are inherited from the profiles referenced by each entry.

---

# ============================================================================
# DATABASE RULES
# ============================================================================

Mount ID:
Permanent gameplay identifier.

Asset ID:
Identifier of the mounted creature sprite.

Icon ID:
Identifier used in the inventory, collection and stable interfaces.

Scaling Profile:
Defines movement speed, carrying capacity, durability and resistance.

Upgrade Profile:
Defines the mount's possible progression and upgrade requirements.

Acquisition Profile:
Defines how the mount is obtained.

Recovery Profile:
Defines the cost and conditions required to recover the mount.

Ability Profile:
Defines any passive or active mount-specific effect.

All mount variants inherit the same base entry.

Generated identifiers follow this format:

MNT-0001-T2
MNT-0001-T3
MNT-0001-T4
MNT-0001-T5
MNT-0001-T6
MNT-0001-T7
MNT-0001-T8

Generated assets follow the same format.

Example:

Gameplay Item:
MNT-0001-T6

Mounted Asset:
MNT-0001-T6

Inventory Icon:
ICO-MNT-0001-T6

Display Name:
Horse T6

# ============================================================================
# EQUIPMENT RULES
# ============================================================================

A player may own multiple mounts.

A player may equip only one active mount at a time.

The active mount determines:

- World travel speed
- Encounter transition speed
- Carrying capacity
- Mount durability
- Mount passive effect
- Recovery cost

A mount does not occupy a standard character equipment slot.

Mounts are managed through:

- Character equipment interface
- Mount collection interface
- Stable Master service

A mount may not be changed during active combat.

A mount may not grant direct weapon damage unless explicitly defined by a
future combat mount system.

Version 1 mounts are utility mounts.

---

# ============================================================================
# COMBAT RULES
# ============================================================================

Mounts are not directly controlled during standard combat.

Mounts do not perform basic attacks.

Mounts do not use autonomous combat abilities.

Mount bonuses may affect combat indirectly through:

- Encounter start timing
- Initial defensive shield
- Retreat speed
- Carrying capacity
- Travel efficiency
- Resource gathering efficiency

Any combat-related mount effect must be defined by its Ability Profile.

A mount cannot replace the player's armor, weapon or off-hand statistics.

---

# ============================================================================
# DURABILITY RULES
# ============================================================================

Mount durability represents the mount's resistance to damage or defeat during
dangerous activities.

Durability may be reduced by:

- Player defeat
- Failed expedition
- Dangerous biome travel
- Special encounter mechanic
- Mount-specific event

Durability does not decrease during safe town interactions.

At zero durability, the mount becomes unavailable.

An unavailable mount must be recovered through the Stable Master.

Durability values are defined in **DB_PROGRESS_RULES.md**.

---

# ============================================================================
# RECOVERY RULES
# ============================================================================

Mount recovery requires one or more of the following:

- Silver
- Time
- Recovery material
- Stable service
- Progression currency

Recovery does not create a new mount.

Recovery restores the existing canonical mount instance.

Recovery costs depend on:

- Mount tier
- Mount role
- Mount rarity
- Mount durability
- Recovery Profile

Recovery values are defined in **DB_ECONOMY.md**.

---

# ============================================================================
# CARRYING CAPACITY RULES
# ============================================================================

Mount carrying capacity increases the maximum inventory weight available to
the player.

The carrying bonus is active only while the mount is equipped.

The bonus remains active during gathering and travel.

The bonus may become inactive after mount defeat if defined by the gameplay
systems.

Carrying capacity does not increase:

- Bank storage
- Mail storage
- Task reward storage
- Account-wide storage

Capacity values are generated through the mount's Scaling Profile.

---

# ============================================================================
# MOVEMENT RULES
# ============================================================================

Mount movement speed affects:

- World map travel duration
- Expedition transition duration
- Automated travel duration
- Return-to-town duration

Mount movement speed does not modify:

- Character basic attack speed
- Ability casting speed
- Combat animation speed
- Enemy movement speed

Fast travel mounts must not completely invalidate standard mounts.

Movement benefits must be balanced against:

- Durability
- Carrying capacity
- Recovery cost
- Acquisition difficulty

---

# ============================================================================
# UPGRADE RULES
# ============================================================================

Mount upgrades may increase:

- Tier
- Movement speed
- Carrying capacity
- Durability
- Resistance
- Passive effect strength

Mount upgrades may require:

- Previous-tier mount
- Silver
- Leather
- Cloth
- Metal
- Rare creature material
- Boss material
- Stable service

An upgrade preserves the mount family.

Example:

Horse T4

may become:

Horse T5

It may not become:

Direwolf T5

A mount's base identity cannot be modified by upgrading.

---

# ============================================================================
# ACQUISITION RULES
# ============================================================================

Mounts may be acquired through:

- Stable Master purchase
- Crafting
- Task reward
- Boss reward
- Monster material exchange
- Progression milestone

Every acquisition method references a canonical Mount ID.

Procedural systems may select eligible mount rewards but may not generate new
mount names or identities.

# ============================================================================
# GENERATION RULES
# ============================================================================

Each mount generates tier variants according to its Tier Range.

Example:

Base Mount:
MNT-0001

Generated Variants:
- MNT-0001-T2
- MNT-0001-T3
- MNT-0001-T4
- MNT-0001-T5
- MNT-0001-T6
- MNT-0001-T7
- MNT-0001-T8

Each generated variant receives:

- The same mount name
- The same mount family
- The same mount role
- The same upgrade profile
- The same acquisition profile
- The same recovery profile
- The same ability profile
- The tier-specific visual asset
- The tier-specific inventory icon
- Statistics generated from its scaling profile
- Acquisition values generated from its acquisition profile
- Recovery values generated from its recovery profile

Only the following values may be generated procedurally:

- Movement speed
- Carrying capacity
- Durability
- Physical resistance
- Magical resistance
- Recovery cost
- Recovery duration
- Upgrade cost
- Acquisition cost
- Passive effect strength

No generated system may modify:

- Mount ID
- Mount name
- Mount family
- Mount role
- Asset ID
- Icon ID
- Scaling Profile
- Upgrade Profile
- Acquisition Profile
- Recovery Profile
- Ability Profile
