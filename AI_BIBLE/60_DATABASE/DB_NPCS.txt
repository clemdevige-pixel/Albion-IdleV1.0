# NPC DATABASE

Version: 1.0

This document defines every non-hostile service character available in
Version 1.

Each NPC references the corresponding visual asset defined in
**41_ASSET_MANIFEST.md**.

Numerical values are not stored directly in this document.

Service costs, inventories, unlock requirements and progression values are
inherited from the profiles referenced by each entry.

---

# ============================================================================
# DATABASE RULES
# ============================================================================

NPC ID:
Permanent gameplay identifier.

Asset ID:
Identifier of the NPC sprite.

Icon ID:
Identifier used in menus, maps and service interfaces.

Service Profile:
Defines the primary functionality offered by the NPC.

Inventory Profile:
Defines items sold or handled by the NPC.

Economy Profile:
Defines prices, fees, commissions and value modifiers.

Unlock Profile:
Defines when and how the NPC becomes available.

Dialogue Profile:
Defines contextual messages and interaction text.

Location Profile:
Defines where the NPC appears.

NPC identifiers follow this format:

NPC-0001

Unlike equipment and monsters, standard NPCs do not generate tier-specific
visual variants.

Service values may scale according to the player's progression, location or
item tier.

# ============================================================================
# SERVICE PROFILE RULES
# ============================================================================

A Service Profile defines:

- Available interaction buttons
- Required input items
- Generated output items
- Service duration
- Service restrictions
- Confirmation requirements
- Failure conditions
- Interface layout
- Associated database references

An NPC may offer multiple services through one Service Profile.

A service must not duplicate an existing core menu unless the NPC interaction
is intentionally required by the progression design.

---

# ============================================================================
# SERVICE_BLACKSMITH
# ============================================================================

Available Services:

- Craft Weapon
- Craft Plate Armor
- Craft Off-Hand
- Repair Equipment
- Salvage Equipment

Database References:

- DB_WEAPONS.md
- DB_ARMORS.md
- DB_OFFHANDS.md
- DB_CRAFTING.md
- DB_PROGRESS_RULES.md

Restrictions:

- Only unlocked recipes may be crafted.
- Required resources must exist in the player's inventory or storage.
- Broken equipment must be repaired before it can be equipped.
- Salvaged equipment is permanently destroyed.

# ============================================================================
# INVENTORY PROFILE RULES
# ============================================================================

An Inventory Profile defines:

- Permanent stock
- Rotating stock
- Stock quantity
- Refresh interval
- Unlock conditions
- Purchase limits
- Item rarity limits
- Tier limits
- Price modifiers

Inventory Profiles must reference canonical IDs from the corresponding content
databases.

NPC inventories must never create an item with a non-canonical item ID.

---

# ============================================================================
# ECONOMY PROFILE RULES
# ============================================================================

An Economy Profile defines:

- Purchase price multiplier
- Sale price multiplier
- Service fee multiplier
- Repair cost multiplier
- Upgrade cost multiplier
- Buyback multiplier
- Storage expansion costs
- Reward valuation

All monetary values are calculated through **DB_ECONOMY.md**.

NPC databases must not contain manually duplicated prices.

---

# ============================================================================
# UNLOCK PROFILE RULES
# ============================================================================

An Unlock Profile may use:

- Player level
- Account progression
- Completed task
- Defeated boss
- Reached biome
- Crafted item
- Collected resource
- Currency threshold
- Tutorial completion

Default town NPCs may be available immediately.

Advanced services may remain locked until their associated system is
introduced.

---

# ============================================================================
# DIALOGUE PROFILE RULES
# ============================================================================

Dialogue Profiles define short contextual messages.

Supported contexts:

- First interaction
- Standard greeting
- Service unavailable
- Insufficient resources
- Successful service
- Failed service
- New service unlocked
- Special progression event

NPC dialogue must remain concise.

NPC dialogue must not block repeated service usage.

Dialogue text may be localized without changing the NPC ID or Service Profile.

---

# ============================================================================
# LOCATION PROFILE RULES
# ============================================================================

Location Profiles define:

- Settlement
- District
- World position
- Interaction range
- Availability state
- Map icon
- Interface shortcut eligibility

NPC locations are defined in **DB_WORLD.md**.

A service NPC may also be accessible through a direct interface shortcut after
the player has interacted with that NPC at least once.

# ============================================================================
# GENERATION RULES
# ============================================================================

NPC identities are never generated procedurally.

The following information is always manually defined:

- NPC ID
- NPC name
- Asset ID
- Icon ID
- Role
- Service Profile
- Inventory Profile
- Economy Profile
- Unlock Profile
- Dialogue Profile
- Location Profile

The following values may be generated dynamically:

- Available inventory
- Item tier range
- Service prices
- Repair prices
- Upgrade prices
- Storage expansion prices
- Task reward values
- Dialogue context
- Service availability
- Map visibility
- Interface shortcuts

Dynamic generation must never modify:

- NPC identity
- NPC asset
- NPC role
- Core service type
- Canonical database references
