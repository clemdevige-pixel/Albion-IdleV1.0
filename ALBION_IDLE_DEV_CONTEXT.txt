MONSTER PIPELINE — ARCHITECTURE COMPLETE
----------------------------------------
Live lifecycle:
monsterContentCatalog -> zone encounter pool -> combatEntityFactory -> CombatRuntime / MonsterAbilityRuntime -> combatRewardAdapter -> loot/rewards -> render manifest.

Authority rules:
- Faction = monster family (single concept).
- monsterContentCatalog owns identity, faction, category, tier, combat modifiers, reward modifiers, lootTableId, abilityIds and visualManifestId.
- monsterAbilityContentCatalog owns reusable monster abilities and category cadence.
- economyContentCatalog owns monster loot tables.
- worldContentCatalog normal spawn metadata derives from authoritative zone encounter pools.
- Renderer resolves monsters only through visualManifestId/manifests.
- Runtime must not branch on monster name/ID for monster-specific behavior.

Reward rule:
final reward = progression reward(zone + segment + encounter/boss) × monster modifier.
Zone/segment progression remains the base authority.

Category support:
normal / veteran / elite / boss.
Category defines max active ability slots and cooldown cadence.

Global validation:
- Monster pipeline contract verifies definitions, abilities, loot tables, renderer manifests, zone pool alignment and reward progression.
- Lethal monster abilities call DeathManager; 0 HP correctly transitions hero to defeat.
