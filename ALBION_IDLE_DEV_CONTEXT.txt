14) FIRST END-TO-END PIPELINE CONTENT TEST — DAGGER PAIR
Date/session: 2026-08-10
Status: implementation committed; Vercel/manual validation pending.

Objective:
Add a completely new weapon family and specialization through the refactored pipeline without modifying generic inventory, equipment, combat, crafting runtime, bridge, enchantment, repair, vendor, Fame or persistence systems.

New content:
- Family: dagger / display name Dagues / mastery mastery_dagger.
- Specialization: Paire de dagues / mastery_dagger_pair.
- Combat profile: dagger (existing intrinsic attack speed 1.6/s).
- Handling: two_handed (pair occupies weapon handling and prevents off-hand use).
- T3 item: item_weapon_dagger_t3_pair.
- T4 item: item_weapon_dagger_t4_pair.

Balance chosen against current branch weapons:
- T3 damage: 34 physical at 1.6/s = 54.4 base DPS.
- T4 damage: 58 physical at 1.6/s = 92.8 base DPS.
- Ability: ability_dagger_double_slash / Double entaille.
- Ability description target: 150% physical damage.
- cooldown: 4s.
- bonusDamageRatio: 0.5, following current ability convention where displayed 150% corresponds to +50% ability bonus layer.
- energy cost: 8 (existing runtime still carries energy metadata; no energy-system refactor performed here).
- sell prices: T3 75, T4 210.

Craft:
- standard recipe profile: 6 metal + 2 leather.
- T3 generator automatically produces refined T3 materials only.
- T4 generator automatically produces refined T4 materials + item_weapon_dagger_t3_pair x1.
- no manual Dagger Pair recipe added.

Presentation:

METHODOLOGY LESSONS
-------------------
- Follow actual consumers before editing legacy-looking data.
- Keep generic infrastructure when architectural; retire stale parallel domain records.
- A standard T4+ weapon without T(n-1) is invalid content and should fail loudly.
- Do not fake future artifact mechanics.
- Presentation is explicit where visual differences are real.
- Protect pipeline rules with invariant tests.
- Bridge/UI transport types should not close over content IDs.
- Runtime bootstraps should resolve routes from authoritative catalogs.
- A successful new-family implementation should primarily touch content + presentation, not generic systems.
