15) FIX — MASTERIES UI DERIVED FROM WEAPON CATALOG
Date/session: 2026-08-10
Status: implementation committed; Vercel/manual validation pending.

Trigger:
Manual Dagger Pair validation showed craft, equipment and combat working, but Dagues / Paire de dagues did not appear in the Masteries panel.

Audit finding:
- Gameplay progression was already generic: CombatRewardRuntime resolves the equipped weapon through resolveWeaponMastery and discovers/awards both family and specialization on enemy kill.
- The actual defect was presentation-model duplication: ui/masteries/masteryModels.ts still owned a closed COMBAT_FAMILIES list containing only sword, bow, fire_staff and gloves.
- Therefore every new weapon family required an undocumented UI edit despite the refactored weapon pipeline.

Fix:
- weaponContentCatalog now exposes getWeaponMasteryFamilyDefinitions(), derived from WEAPON_FAMILIES + WEAPON_CONTENT.
- masteryModels removed the closed COMBAT_FAMILIES registry entirely.
- Combat mastery families/specializations are now built from the authoritative weapon catalog.
- Family icon/symbol is resolved from existing equipmentPresentation family presentation; no second icon registry added.
- Added regression test proving mastery_dagger / mastery_dagger_pair render through buildMasteriesModel.

Files modified:
- apps/client/src/data/weaponContentCatalog.ts
- apps/client/src/ui/masteries/masteryModels.ts
- apps/client/src/ui/masteries/masteryModels.test.ts
- ALBION_IDLE_DEV_CONTEXT.txt

Expected result:
After killing an enemy with Dagger Pair, Dagues appears in Combat masteries and Paire de dagues appears as its specialization. Future weapon families declared in the catalog no longer require masteryModels edits.
