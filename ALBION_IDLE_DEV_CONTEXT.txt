21) MONSTER PIPELINE — BLOCK 1 CONTENT AUTHORITY
Date/session: 2026-08-10
Status: implementation committed; Vercel build validated.

Objective:
Remove the hardcoded active bestiary from combatEntityFactory and establish one active monster content authority without migrating the entire older MonsterRuntime lifecycle.

Implementation:
- Added apps/client/src/data/monsterContentCatalog.ts.
- Monster definitions own identity, faction, category, tier, visualManifestId, combat modifiers and tags.
- Zone encounter pools explicitly own normal pool, segment boss and biome boss.
- resolveMonsterForEncounter selects the active monster.
- combatEntityFactory consumes the catalog and only handles ECS combat entity creation.
- SpawnedEnemyResult now carries monsterDefinitionId.
- Existing combat balance/encounter behavior intentionally preserved.
- Added monsterContentCatalog contract tests.

Architecture decision:
Do not wire the old MonsterRuntime/MonsterIntegrationCoordinator into the live client yet. The current CombatRuntime lifecycle remains authoritative until a later migration provides a concrete gameplay benefit.

22) MONSTER PIPELINE — BLOCK 2 REWARDS + LOOT
Date/session: 2026-08-10
Status: implementation committed; Vercel/test validation pending.

Objective:
Make monster identity participate in rewards and loot WITHOUT replacing zone/segment progression scaling.

Reward rule:
final reward = progression reward(zone + segment + encounter/boss) × monster reward modifier.
The progression curve remains authoritative. Monster modifiers are layered on top.

Migration safety:
- All current monster silverMultiplier = 1.0.
- All current monster fameMultiplier = 1.0.
- Therefore current Silver/Fame balance remains unchanged by this migration.
- Boss encounter multiplier already present in getEncounterRewards remains intact.

Implementation:
- MonsterContentDefinition now owns rewards: silverMultiplier, fameMultiplier, lootTableId.
- applyMonsterRewardModifiers centralizes multiplicative reward scaling.
- Added explicit MONSTER_LOOT_TABLES in economyContentCatalog.
- Existing current monster loot tables intentionally reuse current generic drops to avoid hidden rebalance; IDs are now independent and can diverge per monster/faction later.
- Combat enemy spawn registers active EntityId -> monsterDefinitionId identity in activeMonsterIdentity.
- combatRewardAdapter resolves the killed monster from enemyKilled entityId.
- progression rewards are calculated first with getEncounterRewards, then monster modifiers are applied.
- CombatRewardRuntime receives the selected lootTableId instead of always rolling generic combat loot.
- Active monster identity is cleared after kill processing.
- Fallback for non-catalog/test enemies remains multiplier 1 + generic loot table.

23) MONSTER PIPELINE — BLOCK 3 COMBAT BEHAVIOR + ABILITIES
Date/session: 2026-08-10
Status: implementation committed; Vercel build validated; manual combat feel validation pending.

Objective:
Allow monsters to own active combat abilities and category-driven behavior without monster-name conditions in CombatRuntime or Phaser.

Architecture:
- monsterContentCatalog remains the monster authority and now owns ordered abilityIds.
- Added monsterAbilityContentCatalog as the authority for reusable monster ability definitions and category behavior profiles.
- Category profiles define max active ability slots and cooldown cadence for normal/veteran/elite/boss.
- Higher categories can support more abilities and faster authored cooldown cadence without special-case runtime code.
- combatEntityFactory learns the resolved runtime abilities when a monster entity spawns.
- Added MonsterAbilityRuntime: each combat tick it ticks monster cooldowns, respects stun/silence/death, selects the first ready authored active ability, executes it through AbilityManager and applies damage through DamageManager.
- CombatRuntime calls the generic MonsterAbilityRuntime for the active enemy; it contains no monster-name conditions.

Current authored behavior:
- Stonefang Wolf / Razorwing Harpy / Morgana Witch: auto-attack only for now.
- Undead Warrior boss: Heavy Slash, physical 1.35x source damage, authored 10s cooldown; boss category cadence applies 0.75 cooldown multiplier.
- Ancient Rune Golem biome boss: Crushing Blow, physical 1.60x source damage, authored 12s cooldown; boss category cadence applies 0.75 cooldown multiplier.
- Veteran and Elite category profiles are implemented and ready for future bestiary definitions even though no current live monster uses those categories yet.

- apps/client/src/runtime/MonsterAbilityRuntime.ts

Files modified:

Contract validation:

- Ability count cannot exceed category capacity.
- Category cooldown cadence is deterministic.
- Runtime executes only learned ready active abilities.
- Runtime does not execute abilities while dead, stunned or silenced.
- Ability damage uses normal damage processing.
