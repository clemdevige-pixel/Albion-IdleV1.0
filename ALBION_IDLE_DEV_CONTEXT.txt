7) WEAPON PIPELINE STEP 4 — STANDARD CRAFT PROGRESSION
Date/session: 2026-08-10
Status: implementation pushed; Vercel/manual validation pending.

Objective:
Make normal weapon crafting derive from the weapon catalog and enforce the validated tier progression rule without per-tier weapon recipe duplication.

Files modified:
- apps/client/src/data/weaponContentCatalog.ts
- apps/client/src/data/refiningRecipes.ts
- ALBION_IDLE_DEV_CONTEXT.txt

Authoring model added to weaponContentCatalog:
- each specialization now declares a craft rule.
- standard rule contains craft UI family + material profile/quantities.
- Badon declares artifact_pending explicitly.

Validated design rule encoded:
- T3 standard weapon recipe = refined T3 resources only.
- T4+ standard weapon recipe = refined resources of that tier + exactly one same-specialization weapon from T(n-1).
- predecessor lookup is catalog-driven; no item-name parsing/fallback.
- if a standard T4+ weapon has no previous-tier catalog item, recipe generation throws rather than silently producing an invalid recipe.

Current standard material profiles preserve existing recipe quantities:
- Broadsword: 6 metal + 2 leather.
- Longbow: 6 wood + 2 leather + 2 cloth.
- Fire Staff: 4 wood + 4 metal + 2 cloth.
- Spiked Gauntlets: 5 metal + 3 leather.
The material IDs automatically resolve to T3 or T4 refined resources through the existing refining recipe boundaries.

refiningRecipes changes:
- removed manual T3/T4 recipe literals for Broadsword, Longbow, Fire Staff and Spiked Gauntlets.
- STANDARD_WEAPON_CRAFT_RECIPES now generates those recipes from weaponContentCatalog.
- T3 generated recipes do not contain predecessor equipment.
- T4 generated recipes automatically contain the corresponding T3 weapon.
- armor/off-hand recipes remain explicit and unchanged.

Badon handling:
- Badon is marked artifact_pending in weaponContentCatalog.
- Badon is excluded from STANDARD_WEAPON_CRAFT_RECIPES.
- existing Badon T4 material-only recipe is temporarily preserved explicitly as BADON_TEMPORARY_RECIPE so current V1 behavior is not silently removed before artifact content exists.
- this temporary recipe is documented as temporary; it is NOT the target artifact implementation.
- when artifacts are implemented, BADON_TEMPORARY_RECIPE must be replaced by the real artifact recipe path rather than entering the standard predecessor generator.

No intended balance change:
Existing standard T3/T4 resource quantities and T4 predecessor requirements are preserved.

Validation required before next step:
- Vercel build green.
- crafting screen lists Broadsword/Longbow/Fire Staff/Spiked T3 and T4 once each.
- T3 recipes show only resources.
- T4 recipes show correct resources + matching T3 weapon.
- Badon remains visible/craftable with its current temporary requirements and does NOT request Longbow T3.
- craft execution consumes predecessor for standard T4 and produces output normally.
- enchantment still finds refined craft materials through EQUIPMENT_CRAFT_RECIPES.

METHODOLOGY LESSONS
-------------------
- Never assume a legacy component is mounted because its name matches the feature.
- Follow the real render path before editing UI.
- Prefer existing managers/actions over recreating logic.
- Modify authoritative catalogs rather than adding caller conditionals.
- GameScene/CombatRuntime must not gain weapon-name special cases for content additions.
- Search all consumers before deleting exports.
- Separate gameplay metadata from presentation-only metadata.
- Audit aggregate registries for hidden re-declarations after spreads.
- A standard T4+ weapon without its T(n-1) specialization item is invalid content and should fail generation loudly.
- Do not simulate future artifact mechanics with fake generic rules; keep artifact weapons explicitly outside the standard pipeline until their system exists.
