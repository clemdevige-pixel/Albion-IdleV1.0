13) WEAPON PIPELINE STEP 10A — REMOVE STARTER MASTERY COMPATIBILITY ALIASES
Date/session: 2026-08-10
Status: implementation committed; Vercel/manual validation pending.

Objective:
Remove the final starter Broadsword compatibility exports from progressionContentCatalog and make GameContext consume the authoritative weapon mastery route directly.

Audit findings:
- SWORD_MASTERY_ID and BROADSWORD_MASTERY_ID existed only for the GameContext starter bootstrap.
- their values were already derived from resolveWeaponMastery, so they were not an active divergent source, but they remained an unnecessary compatibility layer.
- current combat Fame already resolves equipped mastery routes directly from weaponContentCatalog.

Files modified:
- apps/client/src/state/GameContext.tsx
- apps/client/src/data/progressionContentCatalog.ts
- ALBION_IDLE_DEV_CONTEXT.txt

Changes:
- GameContext imports resolveWeaponMastery directly from weaponContentCatalog.
- starter Broadsword itemId is resolved once to its family/spec mastery route before bootstrap.
- missing starter mastery content fails loudly with an explicit error.
- starter mastery discovery uses route.familyId + route.weaponId.
- SWORD_MASTERY_ID and BROADSWORD_MASTERY_ID compatibility exports removed.
- progressionContentCatalog no longer imports resolveWeaponMastery solely for starter compatibility.
- no gameplay/balance change intended.

METHODOLOGY LESSONS
-------------------
- Follow actual consumers before editing legacy-looking data.
- Keep generic infrastructure when architectural; retire stale parallel domain records.
- A standard T4+ weapon without T(n-1) is invalid content and should fail loudly.
- Do not fake future artifact mechanics.
- Presentation is authored by specialization/family where appropriate; renderer profiles/manifests remain explicit when differences are real.
- Protect content-pipeline rules with invariant tests, not only runtime smoke tests.
- Bridge/UI transport types must not become closed enumerations of content IDs when the catalog is intended to be extensible.
- Runtime bootstraps should resolve content routes from the authoritative catalog instead of relying on compatibility aliases.
