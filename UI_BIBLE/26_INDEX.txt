```text

→ Pixel Art

INTERFACE
→ High Definition
→ Modern MMORPG
→ Dark
→ Black / Dark Brown / Gold
→ Compact
→ Readable
→ Premium
```

The interface should contain useful information without becoming visually overloaded.

---

# Navigation Principle

Albion Idle does not use traditional full-screen menu navigation.

```text
Game World
    +
Persistent UI
    +
Contextual Right Panel
```

Opening a module changes the Right Panel content.

It does not replace the Game World.

---

# Component Principle

UI must be constructed from shared components.

```text
Design Tokens
      ↓
Shared Components
      ↓
Domain Modules
      ↓
Global Interface
```

New components should only be created when existing components cannot correctly satisfy the requirement.

---

# Architecture Principle

UI must be compartmentalized from the first implementation.

```text
UI
├── shell
├── dashboard
├── character
├── inventory
├── masteries
├── production
├── craft
├── bank
├── world
├── combat-hud
└── shared
```

Domains own their own logic.

Large central components, contexts or stores accumulating unrelated responsibilities are prohibited.

The architecture must remain maintainable while features are added.

Refactoring must not be systematically postponed until files become monolithic.

---

# Source of Truth

Gameplay systems remain authoritative.

```text
GAMEPLAY
    ↓
UI STATE / ADAPTERS
    ↓
UI
```

The UI displays and interacts with gameplay state.

It does not independently define gameplay rules.

---

# Conflict Priority

When UI documents conflict, use this priority:

```text
00_PRINCIPLES
      ↓
Gameplay Source of Truth
      ↓
UI Architecture
      ↓
Global Layout
      ↓
Design System
      ↓
Module Specification
```

Gameplay behavior must never be changed merely to satisfy an outdated UI document.

If a conflict is discovered, the relevant UI documentation must be corrected.

# Before Implementation

The UI Bible does not mean implementation should begin immediately.

The visual direction must first be validated through mockups.

Workflow:

```text
UI BIBLE
   ↓
GLOBAL 1920×1080 MOCKUP
   ↓
VISUAL ITERATIONS
   ↓
RIGHT PANEL MODULE MOCKUPS
   ↓
DESIGN TOKENS FINALIZATION
   ↓
IMPLEMENTATION PLAN
   ↓
PROGRESSIVE MIGRATION
```

Exact dimensions and visual tokens are finalized during the mockup phase.

---

# Reference Mockup

Primary reference resolution:

```text
1920 × 1080
```

The first mockup must validate:

- Header
- Game World proportions
- Right Panel proportions
- Bottom Bar
- Combat HUD
- Navigation
- Overall visual hierarchy
- Information density

The global structure must be validated before producing every individual module mockup.

---

# Implementation Rule

Before implementing a UI feature:

1. Identify the relevant UI Bible documents.
2. Verify the gameplay source of truth.
3. Identify the owning UI domain.
4. Reuse existing shared components where possible.
5. Verify that the implementation does not introduce cross-domain coupling.
6. Implement the smallest coherent scope.
7. Validate visual consistency.

Do not implement first and reorganize later.

---

# Documentation Rule

When a future UI decision modifies an established rule, the UI Bible must be updated.

The documentation should describe the interface that actually exists.

Outdated specifications must not silently remain authoritative.

---

# Final Principle

The objective of the UI Bible is not only to make Albion Idle visually better.

It exists to ensure that the interface remains:

```text
COHERENT
READABLE
MODULAR
EXTENSIBLE
MAINTAINABLE
```

from the beginning of the redesign to the long-term evolution of the game.
